# Карта покрытия Бишкека — ТЗ 7, Осенний хакатон INAI 2026

По замерам сигнала строим карту покрытия сеткой 200×200 м, находим слабые зоны и выбираем
две площадки для новых базовых станций, которые закрывают больше всего слабых квадратов.

## Запуск

Нужен Python 3.10+.

```bash
python -m venv .venv
# Windows:  .venv\Scripts\activate      Linux/macOS:  source .venv/bin/activate
pip install -r requirements.txt

python main.py --data data/sample --out out
```

Одна команда на данных жюри (файлы `measurements.csv`, `towers.csv`, `candidates.csv` в одной папке):

```bash
python main.py --data <папка_с_данными> --out out
```

Или по отдельным путям: `--measurements … --towers … --candidates …`.

**Результат в `out/`:**

| Файл | Что внутри |
|---|---|
| `result.json` | Ровно формат ТЗ: `worst_cells`, `best_candidates`, `dropped_rows`, `covered_weak_cells` |
| `details.json` | Причины отбраковки, координаты худших квадратов, отклонённые площадки, жадный против перебора, день/ночь |
| `coverage_map.html` | Интерактивная карта, открывается в браузере двойным кликом (нужен интернет: Leaflet и подложка OSM грузятся из сети) |

Код возврата `0` — успех, `2` — проблема с входными файлами (нет файла или нужных колонок).

### Параметры

| Флаг | По умолчанию | Зачем |
|---|---|---|
| `--bounds lat_min,lat_max,lon_min,lon_max` | `42.78,42.95,74.45,74.75` (Бишкек) | Границы района для отсева координат и начало сетки |
| `--dedup-on lat,lon,timestamp` | все поля замера | Что считать дублем |
| `--day-hours 8,20` | `8,20` | Дневные часы для сравнения день/ночь |
| `--no-map` | — | Только JSON, без карты |

## Что сделано

**Обязательные пункты:**
1. Очистка: нечисловые и пустые значения, дубли, RSRP вне `[-140; -44]` (границы включительно),
   координаты вне района. Выводится общее число отброшенных строк и разбивка по причинам.
2. Сетка 200×200 м, медиана RSRP по квадрату; квадраты, где меньше 5 замеров, не учитываются.
3. Цвета: зелёный при `≥ -90`, жёлтый при `-105…-90`, красный при `< -105`.
4. Топ-3 худших квадрата (минимальная медиана).
5. Выбор двух площадок: красные квадраты в радиусе 1 км (формула гаверсинуса) без двойного учёта.
   Площадки ближе 500 м к существующей БС исключаются.

**Бонусы:**
- **Жадный алгоритм против полного перебора.** Оба считаются, результат на карте и в `details.json`.
  Контрпример, где жадный проигрывает, есть в `tests/test_placement.py`.
- **День против ночи.** Отдельные слои сетки и число красных квадратов днём и ночью.
- **Тепловая карта слабого сигнала.** Отдельный слой.
- **Своя пара площадок.** Любые две площадки выбираются кликом на карте или в списке; покрытие
  пересчитывается сразу, с подсказкой, сколько не хватает до оптимума.

**Карта** (`coverage_map.html`, Leaflet, без серверной части):
- шкала RSRP — гистограмма медиан с порогами −105 и −90; она же легенда и фильтр классов;
  при наведении на квадрат по шкале бегает стрелка с его значением;
- переключатель «всё время / день / ночь», тепловая карта, зоны 500 м вокруг БС;
- худшие квадраты кликабельны — карта приближает квадрат и показывает его медиану;
- отклонённые площадки видны с причиной («308 м до T01»);
- работает на телефоне, управляется с клавиатуры.

## Как это работает

```
CSV → loader (csv-модуль, всё как строки) → clean → grid → placement → result.json / details.json / карта
```

- **Чтение.** Используем модуль `csv`, а не `pandas.read_csv`. Строка с лишними или недостающими
  полями не роняет программу и не теряется молча, а попадает в отброшенные. Поддерживаются BOM,
  разделитель `;` и синонимы колонок (`latitude`, `rsrp` и т. п.).
- **Порядок очистки:** нечисловые → дубли → RSRP → границы. Итоговое `dropped_rows` от порядка
  не зависит: остаются ровно уникальные валидные строки. Порядок влияет только на разбивку по причинам.
- **Сетка.** Локальная равнопромежуточная проекция с началом в юго-западном углу района. Квадрат
  `r{строка}_c{столбец}` (строки с юга на север, столбцы с запада на восток). Искажение на районе
  ~20 км меньше 0,1%.
- **Выбор.** Пар всего C(20,2) = 190, поэтому полный перебор даёт точный оптимум за миллисекунды.
  При равенстве побеждает первая пара в порядке файла; все равные пары записаны в `details.json`.

## Допущения (уточнить у организаторов)

| Вопрос | Что сделано сейчас | Как поменять |
|---|---|---|
| Границы района | bbox Бишкека | `--bounds` |
| Дубль — это… | полное совпадение `lat, lon, rsrp, timestamp` после разбора чисел | `--dedup-on` |
| Битый `timestamp` | строка **не** отбрасывается (в ТЗ нет такого правила), но в день/ночь не идёт | — |
| Формат `worst_cells` | id квадрата `r32_c38`; центр и медиана в `details.json` | `covmap/grid.py: cell_id` |
| Расстояние до квадрата | до центра квадрата, `≤ 1000 м` | `Config.coverage_radius_m` |
| «Ближе 500 м» | `< 500` м исключается, ровно 500 — допустимо | `Config.min_tower_distance_m` |
| Числа вида `42,87`, `−95` | не число → отбрасывается | `covmap/clean.py: to_number` |

## Тесты

```bash
python -m pytest
```

31 тест: гаверсинус, размер квадрата, пороги цветов, каждое правило очистки (включая границы
диапазона, BOM, `;`, короткие строки), правило 500 м, радиус 1 км, отсутствие двойного учёта,
контрпример для жадного алгоритма, сквозной прогон на сгенерированных данных с известным числом мусора.

Тестовый датасет с заранее известным мусором (ожидаемые числа пишутся в `expected.json`):

```bash
python -m covmap.sample_data --out data/sample
```

```

covmap/clean.py         очистка и отчёт по причинам
covmap/geo.py           гаверсинус, матрица расстояний
covmap/grid.py          сетка 200 м, медианы, цвета, худшие, день/ночь
covmap/placement.py     правило 500 м, покрытие, перебор и жадный
covmap/viz.py           данные для карты (JSON в шаблон)
covmap/templates/       интерфейс карты: HTML + CSS + JS на Leaflet
covmap/sample_data.py   генератор данных с мусором
tests/                  pytest
```
